# Recursion `0.2.0-alpha.3`

`0.2.0-alpha.3` is the refactored execution release for Recursion. It replaces the old whole-run scheduling model with checkpointed, dependency-aware execution while keeping the product boundary the same: Recursion prepares bounded scene guidance for SillyTavern and leaves primary story prose generation to the host.

## Refactored execution

The runtime now models Pre-process and Post-process work as registered stages with explicit state, provenance, dependencies, and checkpoint artifacts. Completed work can survive a late failure or user Stop when its source and contract remain valid.

- `Stop` pauses the owned operation, aborts active Recursion work where supported, clears owned prompt lanes once, and preserves accepted upstream work.
- `Resume` continues through the matching native SillyTavern Send, Swipe, or Regenerate action; it does not start provider work directly.
- `Retry Stage` resets only the blocking stage to its configured attempt window.
- `Reprocess from here on the next swipe` queues dependency-aware work without starting it immediately.
- `Full Rebuild` queues one matching rebuild on the next swipe and can be canceled before consumption.
- A new user message always starts a fresh turn and cannot inherit a queued action from the prior turn.

Progress rows expose one contextual action at a time, with accessible labels and tooltips for Stop, Resume, Retry, Reprocess, and queued-action cancellation. The advanced `Attempts per step` setting controls automatic model attempts from one through five. It does not retry SillyTavern's primary story generation and does not impose a default generation timeout.

See [Runtime Turn Sequence](../technical/RUNTIME_TURN_SEQUENCE.md), [Recursion Technical Manual](../technical/RECURSION_TECHNICAL_MANUAL.md), and the [resumable execution verification record](../verification/2026-07-29-resumable-pipeline-execution.md).

## Provider and pipeline contract

Recursion now uses SillyTavern Connection Profiles as the provider boundary. Recursion stores profile selection and policy state, while SillyTavern owns credentials, endpoints, model routing, and generation presets.

- `Segmented` makes narrow independent card requests and preserves successful slots when another slot fails.
- `Fused` requests a larger structured bundle from a profile that has passed the Fused certification checks.
- A profile that is not Fused-certified downgrades to Segmented before sending a Fused request.
- A partially useful Fused response keeps valid requested cards and repairs only unresolved families through Segmented.
- A Fused response with no useful accepted cards falls back to the complete Segmented path.
- Profile certification covers connectivity, a single-card contract, and a representative Fused bundle. Changes to the selected profile or generation policy invalidate the prior certification.

The provider settings contract is documented in [Provider Setup](../user/PROVIDER_SETUP.md) and [Model Calls and Provider Routing](../technical/MODEL_CALLS_AND_PROVIDER_ROUTING.md).

## Fresh turns, reuse, and recovery

Prepared work is bound to the exact chat, source revision, settings, provider policy, pipeline, and dependency contract that produced it. Unchanged swipes may reuse compatible checkpointed work. Source, settings, provider, pipeline, prompt, stage, dependency, or artifact-integrity drift makes incompatible work stale and prevents it from being resumed or installed.

Post-process operations retain the original assistant response until a validated host commit succeeds. Unified and Progressive flows checkpoint guidance and drafts, and host mutation is idempotent so a resumed operation cannot append the same swipe or repeat an already committed replacement.

See [Cache Use and Reuse](../architecture/CACHE_USE_AND_REUSE_SPEC.md), [Turn-Scoped Reuse and Host-Owned Resume](../verification/2026-08-01-turn-scoped-reuse-and-host-owned-resume.md), and [Post-process Cards Runtime](../architecture/POST_PROCESS_CARDS_RUNTIME.md).

## Storage and privacy

Checkpoint artifacts are isolated from compact manifests. Manifests retain bounded execution metadata; resume-only prompts, cards, guidance, packets, and drafts live in artifact records and are pruned when they become stale or unusable. Successful Post-process settlement removes intermediate guidance and draft bodies.

Recursion diagnostics and release artifacts must not contain Connection Profile ids, endpoints, credentials, authorization headers, raw prompts, raw model output, hidden reasoning, full transcript text, or stack traces. Reset Turn Cache clears Recursion-generated work for the active turn without changing SillyTavern messages.

See [Storage and Diagnostics](../technical/STORAGE_AND_DIAGNOSTICS.md) and [Prompt Privacy and Safety](../user/PROMPT_PRIVACY_AND_SAFETY.md).

## Upgrade expectations

This is an alpha contract replacement. Recursion does not preserve obsolete pre-alpha execution artifacts, old provider setup shapes, or hypothetical legacy runtime paths. After updating, review the current Connection Profile selection and run profile certification before relying on Segmented or Fused work.

The release gate checks the package version, extension manifest, persisted runtime version, release indexes, current documentation vocabulary, provider-contract guidance, and focused regression coverage.

## Known alpha constraints

- Utility remains the required operational lane; Reasoner is optional and policy-routed.
- Provider behavior depends on the selected SillyTavern Connection Profile and its current certification state.
- Recursion does not automatically retry SillyTavern's primary story generation.
- Slow local or remote provider calls may continue until they return, fail, or the operator stops them.
- A provider may charge for a request that fails before its result reaches Recursion; an automatic retry cannot guarantee cost recovery.
- Live-host evidence remains environment-specific; deterministic tests and the alpha gate are the baseline release evidence for this source tree.
