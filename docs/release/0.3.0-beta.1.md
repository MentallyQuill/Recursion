# Recursion 0.3.0-beta.1

Release documentation dated September 24, 2026. This beta consolidates the changes from September 17–24, with implementation history through `081aa157`. Earlier release notes remain historical checkpoints; current manuals describe the active contract.

## Card selection that respects your deck

- Every runnable Priority card is mandatory in Auto, including authored cards. Refinement cards are mandatory in both Auto and Manual. Required cards follow deck order and can exceed the ordinary card cap; ordinary cards use the remaining capacity.
- Fused and Segmented execute the same finalized card plan. Low targets Min Cards, Medium and High use the rounded-down Min/Max midpoint, and Ultra targets Max Cards. Authored cards count toward the target. Multiple source facets of one generated family share a generated slot.
- Auto preserves the Arbiter's scene-specific ranking. Selection variety can vary the last optional slot without disturbing mandatory cards or earlier choices. Its default is Low; Off, Medium, and High are also available.
- Card cooldown excludes recently used optional source cards for 0–10 completed response turns. It defaults to 0, is ignored in Manual, and never excludes Priority or Refinement cards. A strict cooldown can legitimately produce a smaller optional hand.
- Final coverage validation checks the planned hand against the actual selected cards and active deck identities. Missing planned work blocks preparation instead of installing an incomplete packet.

See [Card Deck and Hand](../technical/CARD_DECK_AND_HAND.md) and [Behavior Settings](../design/BEHAVIOR_SETTINGS_POLICY_SPEC.md).

## Refinement before narration

The new Refinement state requests scene-analysis review before Guidance is composed. Auto cycles Off → Active → Priority → Refinement; Manual cycles Off → Active → Refinement.

Marked authored instructions first receive a scene-grounded application. Review uses the frozen scene, original instructions, and complete selected hand. An unchanged acceptance is a valid result; a specific finding can trigger one revision and one verification review. Unresolved findings or provider failure block preparation. Saved authored instructions are preserved.

Reviews must explain their assessment using scene evidence and supporting card references, including whether a relevant application was missed. The Viewer exposes the final assessment and accepted outcome. Review commentary is kept out of narrator input, and refinement rounds are shown separately from card counts.

## Optional Realism analysis

Realism cards help ground reactions in the setting and the character's available evidence. Extraordinary claims invite plausible alternatives, questions, and feasible checks; sincerity or one striking detail is not automatic proof. This is contextual analysis, not a requirement that characters reject unfamiliar events or impose real-world rules on every fictional setting.

Characters also distinguish an expressed goal from a claim of capability or success. New intentions and revelations can change which earlier questions matter; unresolved questions need not force the conversation to repeat itself or prevent progress.

## Post-process writing and review

- Utility and Reasoner produce structured editing guidance. A separate writer produces the revised prose.
- Writer can use the current SillyTavern model or a dedicated Connection Profile without changing the main story connection. The profile writer receives the complete draft and bounded editing evidence; the current-model writer retains native host context.
- Unified performs a combined rewrite; Progressive applies categories in deck order. Polish preserves spoken dialogue wording, while Revise permits restructuring and rephrasing within the original intent and events.
- Review before applying holds a candidate for inspection. Compare the original and revision, edit the candidate, keep the original, or request another revision from the original while the source remains eligible.
- Deck Style supplies a brief and optional example. Examples guide style without importing their facts into the scene.
- Source identity, cancellation, exact no-op checks, and application guards protect the selected response. Partial Progressive output is applied only as a new swipe.

See the [operator manual](../user/RECURSION_OPERATOR_MANUAL.md) and [Post-process runtime contract](../architecture/POST_PROCESS_CARDS_RUNTIME.md).

## Guidance, Fused, and recovery

- Explicit Fused selection no longer depends on profile certification. Certification remains diagnostic, and configured profiles still need to satisfy runtime validation.
- Fused preserves valid returned cards, records item-specific failures, and repairs unresolved work. Recovery progress reconciles parent and child states instead of leaving repaired work marked as failed.
- Guidance requires valid model-composed instructions. Required preparation failure prevents unguided host narration; successful internal repair stays quiet while details remain inspectable.
- Selected chat messages retain their complete text, and authored card instructions retain meaningful line structure. Message-count selection still bounds the context window; these changes do not promise unlimited provider context capacity.
- Provider rate limits receive eight automatic capacity retries per stage, separate from ordinary model correction attempts. Backoff starts at two seconds and doubles to a sixty-second ceiling; a longer Retry-After wins. Calls sharing the profile share its cooldown, while other profiles remain independent.
- Stop cancels waiting work. Resume and Retry preserve inherited cooldowns and completed checkpoints; explicit Retry opens a new allowance. Exhaustion remains a rate-limit failure rather than being mislabeled as invalid card content. Recursion does not automatically retry SillyTavern's primary story generation.

See [Provider Setup](../user/PROVIDER_SETUP.md) and the [provider contract](../architecture/PROVIDER_AND_GENERATION_SPEC.md).

## Inspection, providers, and compatibility fixes

- Deck Viewer displays complete card text, avoids duplicate text, and preserves scroll position during refresh.
- Diagnostics export through a JSON file download, including on plain HTTP/LAN hosts. Turn hashing supports those hosts, and scheduler startup no longer loops on the affected HTTP path.
- Provider work includes active-key fallback, restored planning controls, bounded profile concurrency and recovery, and clearer call latency diagnostics. Utility defaults to minimal reasoning; actual behavior depends on provider support.
- Output allowances, turn freshness, and post-processing bounds were corrected. These changes improve execution controls; they are not a guarantee of lower cost or better prose from every model.

## Updating and trying the beta

Update the Recursion extension in SillyTavern and reload the page. The minimum declared client version remains 1.18.0, and automatic extension updating remains disabled in the manifest.

Inspect your active deck and provider selections. Try Refinement on a small number of important cards first because review can add model calls. Auto variety defaults to Low and cooldown to Off. Post-process remains optional and off by default; choose its writer and application mode before enabling it. Use Last Brief and the Viewer to inspect the resulting hand, Guidance, and assessments.

This is a beta checkpoint under the current V1 contract. Historical data shapes are not a compatibility promise. Screenshots in older guides may predate these controls; the current written manuals and source define behavior.
