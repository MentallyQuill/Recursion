# Recursion Cost Research

This document summarizes the current token and call-cost shape of Recursion. It is a planning and operator reference, not a billing engine. Recursion does not currently store price-per-token, token multipliers, provider billing rates, or monthly quota settings in runtime configuration.

Cost in this document means one of three things:

- provider calls Recursion makes before or after the host generation;
- tokens sent to, returned by, or injected into model calls;
- externally billed budget tokens after a provider-specific multiplier is applied outside Recursion.

## Current Runtime Position

Recursion uses a two-lane provider model:

| Lane | Required | Typical cost role |
| --- | --- | --- |
| Utility | Yes | Fast, cheap, JSON-first operational work: Arbiter, Segmented card generation, Fused bundles at Low/Medium, Pre-process/Post-process Guidance, and provider tests. |
| Reasoner | No | Optional synthesis lane selected by Reasoning Level when its selected profile is eligible for the requested stage. It is used for `reasonerComposer`, and for Arbiter/card/Fused work at higher reasoning levels. |

Recursion does not have a Writer lane. The final story prose is generated by SillyTavern's normal host model after Recursion installs its prompt packet.

Each lane uses one selected SillyTavern Connection Profile. SillyTavern owns the endpoint, credentials, model selection, generation preset, and instruct preset. Recursion stores only the selected profile id, generation policy, sampler overrides, output ceiling, revision, and privacy-safe certification result.

Provider prompts, provider responses, profile objects, credentials, hidden reasoning, full transcript text, and full prompt packets must not enter saved settings, journals, diagnostics, browser storage, or test artifacts.

## Billing Configuration Boundary

No runtime monetary billing configuration exists today. Source and docs use token-cost language only for planning:

| Concept | Meaning |
| --- | --- |
| `tokenCost` on cards | A card prompt-footprint estimate, not a provider bill. |
| `tokenEstimate` in catalog entries | A planning estimate used for hand and budget shaping. |
| Footprint section budgets | Character caps for Guidance, Card Evidence, and Guardrails. |
| Provider output ceiling | Per-lane hard ceiling, default `8192`; each stage applies a smaller role-specific budget. |
| External multipliers | Provider- or subscription-specific accounting outside Recursion. |

If a provider bills a model at 2x, Recursion does not know that natively. Operators should apply that multiplier externally when estimating budget consumption.

## Default Settings That Affect Cost

| Setting | Default | Cost impact |
| --- | ---: | --- |
| `pipelineMode` | `segmented` | Runs requested card families as separate, narrow model stages. |
| `modelAttemptsPerStep` | `2` | Total automatic attempts available to each Recursion model stage; only a dispatched model call consumes an attempt. |
| `reasoningLevel` | `medium` | Utility handles Arbiter, cards, and Fused bundles by default; an eligible Reasoner may handle composition. |
| `minCards` / `maxCards` | `3` / `10` | Shape card job pressure; Medium/High use the normalized midpoint as a cap. |
| `promptFootprint` | `normal` | Controls final injected packet size budget. |
| `providerVisibleMessages` | `12` | Recent visible messages sent to Recursion provider calls. |
| `sourceWindowMessages` | `20` | Recent visible messages considered for source freshness and evidence windows. |
| `sourceWindowCharacters` | `12000` | Character cap for the source freshness window. |
| `postProcess.enabled` / `postProcess.flow` / `postProcess.applyMode` | `false` / `unified` / `as-swipe` | Adds one structured Post-process guidance stage and one native host quiet rewrite after generation. Progressive may repeat the guidance/rewrite pair per enabled category. |
| Utility output ceiling | `8192` | Hard ceiling; stage-specific budgets normally request substantially less. |
| Reasoner output ceiling | `8192` | Hard ceiling; stage-specific budgets normally request substantially less. |

## Pipeline Call Shape

### Segmented

Segmented is the reference foreground path and the default. It favors smaller or simpler local models by giving each requested card family a narrow contract.

| Stage | Call count | Lane |
| --- | ---: | --- |
| Arbiter | Usually 1 | Utility at Low/Medium; an eligible Reasoner at High/Ultra. |
| Card generation | 0 to selected budget | Utility at Low/Medium; mixed or eligible Reasoner-heavy at High/Ultra. |
| Guidance Composer | Usually 1 when composing a packet | Utility. |
| Reasoner Composer | 0 or 1 | An eligible Reasoner when Medium+ policy selects it. |
| Post-process | 0 or 1 Unified guidance stage plus native host rewrite; Progressive repeats by category | Guidance stays on Utility or the selected eligible Reasoner lane; native host quiet generation writes the response. |

Accepted checkpoints and exact-turn unchanged-swipe reuse can reduce or remove downstream calls. A stopped or failed operation resumes from its earliest incomplete stage rather than paying again for every accepted upstream stage.

### Fused

Fused keeps the normal foreground lifecycle, but replaces many card calls with one `fusedCardBundle` call.

| Stage | Call count | Lane |
| --- | ---: | --- |
| Arbiter | Usually 1 | Same policy as Segmented. |
| Fused card bundle | 1 primary call | Utility at Low/Medium; an eligible Reasoner at High/Ultra. |
| Fused repair | 0 to missing/invalid family count | Segmented card calls for damaged siblings only. |
| Guidance Composer | Usually 1 when composing a packet | Utility. |
| Reasoner Composer | 0 or 1 | An eligible Reasoner when Medium+ policy selects it. |
| Post-process | 0 or 1 Unified guidance call plus native host rewrite; Progressive repeats by category | Guidance stays on Utility or the selected eligible Reasoner lane; native host quiet generation writes the response. |

Fused is usually cheaper than Segmented when the model returns trustworthy multi-card JSON because it collapses card setup overhead into one larger structured request. If any useful bundle item survives, only damaged siblings are repaired. A bundle with zero useful cards falls back to the Segmented card path, so an unreliable Fused model can cost more than selecting Segmented initially.

## Token Budget Ranges

These are planning ranges from the current call shapes and bounded prompt windows. Real usage depends on provider-visible message length, selected card count, valid checkpoint or unchanged-swipe reuse, footprint, host context, provider hidden reasoning, model attempts, and output length.

### Recursion Background Input Tokens

| Component | Segmented | Fused |
| --- | ---: | ---: |
| Arbiter | 2K-8K | 2K-8K |
| Card generation | N x 1K-3K | 2K-6K, plus damaged-sibling repair |
| Guidance Composer | 1K-4K | 1K-4K |
| Reasoner Composer | 0-4K | 0-4K |
| Post-process | 0-20K | 0-20K |
| Approx total | 3K-25K+ | 3K-22K+ before repair or fallback |

### Recursion Background Output Tokens

| Component | Segmented | Fused |
| --- | ---: | ---: |
| Arbiter | 200-500 | 200-500 |
| Card generation | N x 100-300 | 500-2K, plus damaged-sibling repair |
| Guidance Composer | 200-800 | 200-800 |
| Reasoner Composer | 0-800 | 0-800 |
| Post-process | 0-8K | 0-8K |
| Approx total | 400-6K+ | 900-8K+ before repair or fallback |

## Final Prompt Packet Size

Recursion also changes the host generation cost by injecting Guidance, Card Evidence, and Guardrails into SillyTavern's prompt. The final packet is bounded by Prompt Footprint section budgets in characters:

| Footprint | Guidance | Card Evidence | Guardrails | Approx total chars | Approx tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| Compact | 900 | 12,000 | 700 | 13,600 | 3,400 |
| Normal | 1,800 | 30,000 | 900 | 32,700 | 8,200 |
| Rich | 3,200 | 60,000 | 1,200 | 64,400 | 16,100 |

These packet tokens are not a separate Recursion provider call after install. They are extra input context for the host story-generation request.

## Example Estimate: Medium Reasoning, Normal Footprint

This example assumes:

- Utility lane: a 1x utility-class model.
- Reasoner lane: a 2x model such as GLM-5.2 through a SillyTavern connection profile.
- Host generation: the same 2x model.
- Reasoning Level: Medium.
- Pipeline: Segmented.
- Prompt Footprint: Normal.
- Post-process Cards: Off.
- Typical source window: 15-20 visible messages, with provider calls still capped by `providerVisibleMessages`.

At Medium, Arbiter and card generation stay on Utility, `guidanceComposer` stays on Utility, and `reasonerComposer` may add a Reasoner synthesis patch when the selected Reasoner profile is eligible.

| Work | Lane | Raw tokens | Multiplier | Budget tokens |
| --- | --- | ---: | ---: | ---: |
| Arbiter | Utility | ~6,000 | 1x | ~6,000 |
| Card generation, roughly 6 cards | Utility | ~14,500 | 1x | ~14,500 |
| Guidance Composer | Utility | ~6,500 | 1x | ~6,500 |
| Reasoner Composer | Reasoner | ~5,500 | 2x | ~11,000 |
| Host generation with normal packet | Host | ~20,200 | 2x | ~40,400 |
| Approx full turn | Mixed | ~52,700 | mixed | ~78,400 |

Without Recursion, the same host generation might consume roughly `~11,200` raw host tokens, or `~22,400` budget tokens at 2x. In that scenario, Recursion's incremental cost is roughly `~56,000` budget tokens per full Segmented turn before checkpoint/cache reuse, additional attempts, provider hidden reasoning, or optional Post-process work.

If a subscription supplies `60,000,000` monthly budget tokens for `$12`, then each 1,000 budget tokens is roughly `$0.0002`. Under the example above:

| Metric | Approx value |
| --- | ---: |
| Incremental Recursion cost per Segmented turn | ~56,000 budget tokens |
| Incremental dollar cost per Segmented turn | ~$0.011-$0.015, roughly 1-1.5 cents |
| Full turn cost with Recursion | ~78,400 budget tokens |
| Full dollar cost with Recursion | ~$0.016 |
| Monthly turns if every token is spent on this pattern | ~765 turns |

Bottom line: with the medium-reasoning Segmented setup above, Recursion adds about 1-1.5 cents per turn on top of normal SillyTavern generation cost.

Treat those values as order-of-magnitude planning numbers, not a guarantee. Hidden thinking tokens on reasoning models can materially increase billed usage even when visible output is small.

## Cost Levers

Use these controls first when tuning cost:

| Lever | Effect |
| --- | --- |
| Use Low or Medium Reasoning Level | Keeps more work on Utility and reduces Reasoner usage. |
| Use Fused with a strong structured-output model | Reduces card-call overhead when bundle JSON is reliable. |
| Use Segmented with a smaller or less reliable structured-output model | Avoids paying for a failed bundle before individual card calls. |
| Resume from accepted checkpoints | Avoids repeating successful upstream work after a stop or failure. |
| Lower `maxCards` and `minCards` | Reduces card generation and selected evidence. |
| Use Compact Prompt Footprint | Reduces final host prompt injection size. |
| Lower provider-visible and source-window limits | Reduces provider input tokens for long chats. |
| Keep Post-process Cards off | Avoids post-generation guidance and native quiet-rewrite calls. |
| Prefer cache reuse for stable scenes | Lets the Arbiter skip new card generation when safe. |

## Caveats

- Provider hidden reasoning may be billed but not visible in Recursion output.
- Additional model attempts, Fused sibling repair, and full Segmented fallback add calls.
- Recursion sets no default generation timeout. A pending slow call does not consume another attempt, and only model stages consume the configured `Attempts per step` window.
- Recursion does not automatically retry SillyTavern's primary story generation.
- Providers can charge for responses that fail to reach Recursion; checkpoints prevent needless downstream replay but cannot guarantee recovery of provider charges.
- Host presets, character context, lorebooks, and other SillyTavern extensions can dominate final host-generation cost; Recursion only controls its own injected packet.
- A healthy Reasoner lane is optional. If unavailable, Recursion composes through Utility and records fallback metadata.
- Exact monthly cost depends on the external provider's accounting rules. Recursion currently exposes token-shaping controls, not provider billing controls.
